# 0004 — Accounts, JWT and Alembic migrations

Status: accepted (lab 21, M1)

## Context

Lab 31 shipped a deployed API with fake auth: one shared `X-API-Key` and `owner_id` / `session_id`
UUIDs generated in the browser. Anyone who knows a UUID reads that space. The schema was created
by `init_schema` at every app startup (idempotent SQL, no history). Lab 21 needs real accounts and
versioned migrations. M1 adds both without changing the existing endpoints (M2 does that).

## Decision

| Topic | Decision |
|---|---|
| Migrations | Alembic with **raw SQL** (`op.execute`), no ORM metadata. `env.py` takes the URL from `get_settings().database_url` and rewrites `postgresql://` to `postgresql+psycopg://`. |
| Baseline | `0001` = the exact current schema, all `IF NOT EXISTS`: a no-op on the live DB, a full build on an empty one. Downgrade drops tables in FK order, not the `vector` extension. Alembic is the only schema owner; `init_schema` is gone from the app. |
| Users | `0002`: `users(id uuid, email unique, password_hash, created_at)` with `CHECK (email = lower(email))`. |
| Password hash | argon2id via `pwdlib` (`PasswordHash.recommended()`), run in `asyncio.to_thread` because it is CPU-bound. |
| Token | JWT HS256, 24 h, claims `sub`, `iat`, `exp`. Decoded with explicit `algorithms=["HS256"]` and required `exp`, `sub`. `JWT_SECRET` is mandatory (>= 32 chars), the app refuses to start without it. |
| Login | OAuth2 password form (`username` = email), so Swagger's Authorize button works. |
| Login errors | Unknown email and wrong password give the same 401; a dummy hash is verified when the user is missing (no enumeration by message or timing). Register still answers 409 for a taken email: accepted. |
| Duplicate email | The UNIQUE constraint decides; `UniqueViolation` becomes `EmailTaken`. No check-then-insert (race-safe). |
| Registration | Open, plus optional `REGISTRATION_CODE`; a stricter per-IP limit (`AUTH_RATE_LIMIT_PER_MINUTE`, 5) on `/auth/*`. |
| Token storage in the SPA | localStorage (XSS-readable; same trade-off as lab 22). |

## Rejected alternatives

- **SQLAlchemy ORM + autogenerate**: rewriting the tested psycopg `store.py` adds no product value.
- **passlib / python-jose**: unmaintained; FastAPI docs moved to pwdlib + PyJWT.
- **bcrypt / plain SHA-256**: SHA is fast by design, so brute force is cheap; argon2id is memory-hard.
- **HttpOnly cookie**: SPA and API are on different origins, which brings SameSite/CSRF complexity.
- **Keeping `init_schema` next to Alembic**: two schema owners drift apart.
- **Refresh tokens / server-side revocation**: out of scope; logout = the client forgets the token.

## Consequences

- Deploys must run `uv run alembic upgrade head` (wired into Render in M3).
- No autogenerate: every schema change is hand-written SQL in a new revision.
- A leaked `JWT_SECRET` lets anyone forge tokens; rotating it logs everyone out.
- Tokens cannot be revoked before they expire (up to 24 h).
- `X-API-Key` and `owner_id` stopped working in M2 (see Ownership below).

## Ownership (lab 21, M2)

Every data endpoint is scoped to the user in the Bearer token. `X-API-Key`, `APP_API_KEY` and every
`owner_id` field are gone; the user id comes only from `get_current_user`.

| Topic | Decision |
|---|---|
| Foreign id | **404**, the same answer as for a missing id. 403 would confirm that the id exists (a session, document or chunk of someone else), so ids could be probed. 403 is kept for a different case: the registration code. |
| Where it is enforced | **In SQL**: `WHERE id = %s AND user_id = %s` (or `owner_id`). Never "fetch the row, compare the owner in Python": that is one forgotten `if` away from a leak, and it costs a second query. The store returns `None` / `False` for both "missing" and "not yours". |
| Guard test | A test walks every route of the app and requires 401 without a token, except an explicit public list. A new route without the dependency fails the suite. |
| Dependency order | `get_current_user` first, then `limit_per_ip`: unauthenticated requests never touch the limiter. |
| Sessions | Server-side resource: ids are generated by the server, `POST /sessions` creates, `/chat` and `/flashcards` no longer create sessions implicitly. Titles default to "New chat" and become the first 60 characters of the first question. |
| Pagination | Offset (`limit` 1..100, `offset` >= 0) with `total` and `next`. Order is `updated_at DESC, id`: the `id` tie-break keeps pages stable. Cursor pagination was not needed at this size. |
| Account deletion | `DELETE /auth/me`, everything goes by `ON DELETE CASCADE` (sessions -> messages, llm_calls; documents -> chunks). |
| Legacy data | Migration `0003` **deletes** all documents, uploaded chunks and sessions: they belonged to random browser UUIDs and have no account to be assigned to. Shared knowledge-base chunks (`owner_id IS NULL`) stay. Downgrade drops the new columns and foreign keys but cannot restore the deleted rows. It ran on the Neon `dev` branch first; production gets it at the M3 deploy. |
| Logs | One JSON line per request (`mnemonic.access`): method, route template, status, duration, user id, ip. Never headers, query strings, bodies or tokens. |
| `/health` | Liveness only: no auth, no database. |

Known limits: the token is valid until it expires even after logout (no revocation); `POST /sessions`
has no per-IP limit of its own (the user must be logged in); deleting an account does not invalidate
other already-issued tokens by itself, but `get_current_user` looks the user up on every request, so
they stop working at once.

## Tests and delivery (lab 21, M4)

| Topic | Decision |
|---|---|
| Integration tests | `tests/integration/`, marker `integration`, run only with `TEST_DATABASE_URL`. The session fixture drops the `public` schema and runs `alembic upgrade head` in-process (`migrations/env.py` takes the URL from `config.attributes`); tables are truncated between tests. Unit tests keep using `MemoryStore` (fast, no DB). |
| Safety guard | The suite refuses to start (`pytest.exit`) when `TEST_DATABASE_URL` has the same host + port + database as `DATABASE_URL`: the fixture wipes the database it gets. |
| Races | Tested with threads released by a `threading.Barrier`: one email registered twice, N uploads against a limit of 3. |
| CI | GitHub Actions, two jobs (`backend` with a `pgvector/pgvector:pg17` service, `frontend`), `contents: read`, older runs cancelled. `HF_HUB_OFFLINE=1` makes any model download fail. |
| CD | `render.yaml`: `autoDeployTrigger: checksPass` (deploy only after GitHub checks pass), `healthCheckPath: /health`, `alembic upgrade head && uvicorn ...` as the start command (`preDeployCommand` needs a paid plan). |
| SPA preflight | `npm run dev` / `npm run doctor` fetch `<VITE_API_URL>/openapi.json` and require `/auth/register` and `/sessions`, so a wrong URL or an old deploy fails in one line before the app starts. |
